# HUNT Gizmo

Переиспользуемый клиентский редактор положения и вращения. Первая интеграция —
физические рюкзаки `thehunt_inventory` / `thehunt_items`.

## Игроку

Надеть рюкзак → ПКМ по его предмету → **Расположение**. Инвентарь закрывается,
камера показывает спину. ЛКМ тянет ось или кольцо, ПКМ поворачивает камеру,
Shift уменьшает шаг, Tab меняет режим. Enter сохраняет, Esc отменяет.
«Сбросить» показывает базовую посадку; для сохранения сброса нужно нажать Enter.

Перемещение ограничено относительно центра модели на кости спины: X (влево/вправо)
и Z (вверх/вниз) ±12 см, Y (вперёд/назад) от −10 до +8 см, вращение каждой оси
±45° от базовой ориентации. Это ограничения
редактора, а не автоматический подбор по коллизиям одежды. Толщина верхней одежды
учитывается базовым зазором. Общий файл ограничений:
`thehunt_items/shared/backpack.lua`.

Предпросмотр передаётся серверу не чаще одного раза в 300 мс. SQL изменяется только
при сохранении: `thehunt_inventories.metadata.backpackFit`. Настройка принадлежит
экземпляру предмета и сохраняется вместе с его metadata. Сервер проверяет владельца,
персонажа, слот Satchels, тип предмета, конечность чисел и диапазоны. При отмене или
истечении сессии восстанавливается сохранённое значение. Другие клиенты получают
положение через серверное `attachedBackpackFit`; реплики создаются локально при
входе игрока в зону стриминга. Пересоздание объекта при каждом движении не требуется.

## Подключение другого ресурса

Добавить `dependency 'thehunt_gizmo'`. Вызвать после освобождения NUI-фокуса:

```lua
local started = exports.thehunt_gizmo:Start({
    title = 'Расположение',
    value = {x=0,y=0,z=0,rx=0,ry=0,rz=0},
    defaults = {x=0,y=0,z=0,rx=0,ry=0,rz=0},
    limits = {x={-1,1},y={-1,1},z={-1,1},rx={-45,45},ry={-45,45},rz={-45,45}},
    point = function(value)
        -- Вернуть vector3 мирового центра. Изменения x/y/z должны линейно
        -- переводиться в выбранную систему координат (мир/кость/объект).
        return origin + vector3(value.x,value.y,value.z)
    end,
    apply = function(value) -- применить локальный предпросмотр
    end,
    valid = function() return DoesEntityExist(entity) end,
    tick = function(value) -- необязательный heartbeat/отложенная синхронизация
    end,
    camera = function(dx,dy) -- необязательное управление камерой мышью
    end,
    finish = function(saved,value,reason)
        -- Освободить собственную камеру/состояние. saved=true означает намерение
        -- сохранить: результат записи должен отдельно подтвердить ваш сервер.
    end,
})
```

`Start` возвращает false при занятом NUI или уже открытом редакторе.
`exports.thehunt_gizmo:IsActive()` проверяет занятость.
`exports.thehunt_gizmo:Cancel()` отменяет только сессию вызывающего ресурса.
При отмене движок сначала вызывает `apply(initial)`, затем `finish(false,...)`.
При остановке ресурса владельца или самого gizmo фокус освобождается.
Камера, создание сущностей, сеть, права и БД остаются ответственностью интеграции.

## Проверка и запуск

Ресурс включён перед инвентарём в `server.cfg`; подключены зависимости и shared-файл.
Для применения всех изменений требуется плановый перезапуск сервера. Не следует
перезапускать `thehunt_items` посреди действий с предметами: у него есть собственное
оперативное состояние дропов и незавершённых операций.

Статические и mock-проверки не заменяют RedM. После запуска проверить:

1. Рюкзаки на мужском и женском персонаже, с пальто и без; оси идут за мышью,
   при вращении центр остаётся на спине, верхние/нижние пределы приемлемы.
2. Второй клиент видит предпросмотр, сохранение и возврат после Esc.
3. Снять/надеть, сменить рюкзак, переподключиться, уйти и вернуться в зону стриминга.
4. Смерть, потеря предмета, смена персонажа и остановка редактора возвращают управление.
5. В том же месте сравнить `resmon` builder в покое и при движении, затем проверить
   размещение/перемещение/удаление пропа и появление построек при приближении.

Проверки в `tests/` запускаются из корня RedM_Server через Python с `lupa` и
`playwright`; браузерная проверка использует установленный Edge в headless-режиме.
`check.py` проверяет Lua-синтаксис (заменяя RedM hash-литералы перед стандартным Lua
парсером), `behavior_check.py` — серверные операции на mock-БД,
`replica_check.py` — локальные и удалённые реплики с разными server ID / player index,
`engine_check.py` — фокус и завершение сессии, `builder_check.py` — очередь,
`browser_check.py` — мышь, меню, пределы, сброс, Enter/Esc и порядок запросов.

Исправлен резервный ID кости: RDR Spine2 = 14412, а не GTA ID 24818.
Источник: [исследование костей RDR2, femga](https://github.com/femga/rdr3_discoveries/blob/master/boneNames/player_zero__boneNames.lua).
Модель крепится её исходным pivot прямо возле Spine2 с порядком вращения 1.
У этих рюкзаков авторские оси повернуты: attachment X означает высоту, Y — глубину,
Z — боковое смещение. Gizmo переводит их в привычный вид X — бок, Y — глубина,
Z — высота; подписи в редакторе показывают это явно, поэтому красная ось больше
не поднимает рюкзак вверх.
Автоматическая коррекция через `GetModelDimensions` удалена: у части потоковых
YDR/YTYP центр bounds не совпадает с видимой геометрией, из-за чего валидный объект
уходил из кадра, хотя gizmo оставался на спине. Точная посадка хранится в предмете.

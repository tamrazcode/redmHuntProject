# Обновление thehunt_loot — 10 сентября 2026

Исправления и новые возможности внесены в ресурс; сервер и игровая база в ходе работы не перезапускались и не изменялись.

## Генерация и сохранение

- Кулдауны загружаются из БД до начала симуляции. Срок жизни существующего слота сохраняется, а не заменяется на 30 минут при каждом запуске. Для новых бессрочных слотов в БД записывается NULL.
- Обычный цикл запускается при появлении игрока в радиусе активации, когда зона пуста и кулдаун завершён. Частично собранная зона не пополняется на каждом тике. Количество слотов случайное между минимумом и максимумом; при недостатке места их может быть меньше.
- Новое правило «Без повторения типов предметов»: каждый тип выбирается один раз за цикл, с сохранением весов выбора. Число слотов ограничено размером пула.
- Новое правило «Новый цикл только после ухода игроков»: после опустошения зоны игроки должны выйти из радиуса активации. Следующий вход запускает готовую к респавну зону. Правила сохраняются в существующем custom_rules.
- Пустой неудачный цикл получает паузу перед следующей попыткой. Минимальное расстояние между слотами больше не уменьшается автоматически.
- Удалены двойные ключи зон в кэше. Дублирование полигона перемещает также его вершины.
- Изменение параметров существующей зоны и её пула выполняется одной транзакцией. Удаление зоны, пула, слотов и кулдауна также объединено в транзакцию.
- Убран автоматический DROP TABLE при старте. Существующая несовместимая схема требует отдельной диагностики; данные не стираются для её «исправления». Команда явного сброса базы сохранена.

## Подбор и слияния

- Разделение стака использует общий путь подбора: проверяются персонаж, расстояние, целочисленные координаты, принадлежность карманов одежды и границы/занятость ячеек.
- Количество разделяемых предметов должно быть положительным целым числом. Обычный подбор не принимает служебный mutationSequence за количество предметов.
- Подбор и слияния используют блокировки слотов и игрока. Истечение срока жизни и операции редактора учитывают занятой слот.
- Слияние проверяет дистанцию, владельца инвентаря, метаданные и лимит стака. Оба счётчика изменяются одним условным SQL UPDATE; устаревший запрос не должен увеличивать количество предметов.
- В thehunt_items/server/main.lua добавлены два серверных экспорта AcquireLootDropLock / ReleaseLootDropLock. Они используют существующие блокировки обычного дропа и обновляют его серверный кэш после слияния.
- Исправлены аргументы CreateCustomStash и пересечение временных ID с SQL ID.

## Редактор и стриминг

- Живой статус выбранной зоны: количество слотов, наличие игроков, кулдаун, ожидание ухода и текущая операция.
- Настройка радиуса активации, два новых правила генерации, отображение относительного веса предметов в процентах.
- Проверка параметров на клиенте и сервере. Статус сохранения, блокировка повторного сохранения, Ctrl+S, сообщение об ошибке с сохранением черновика.
- Подтверждение потери изменений при закрытии и переходе через список зон. Сохранение другого администратора не перезаписывает локальную рабочую копию.
- Удалённая зона исчезает из списка после подтверждения сервера. Добавлена кнопка очистки тестовых пропов; отменённая загрузка предпросмотра больше не создаёт их после закрытия.
- Ввод в редакторе блокирует игровые действия; свободная камера продолжает использовать отключённые контролы. При остановке ресурса освобождаются камера и NUI-фокус.
- Ограничена параллельная загрузка моделей, добавлена пауза для несуществующих моделей и проверка отмены загрузки. Применяется сохранённый render_radius слота.
- Проверены компоновки 1440×900 и 1920×1080. CSS blur не используется.

## Проверки и практические ограничения

Пройдены разбор Lua (19 файлов, включая адаптер thehunt_items), браузерные проверки NUI и сценарные тесты с подменёнными RedM/MySQL API: таймеры, генерация, режим ухода, разделение, ошибки вставки, слияния, сохранение суммарного количества и освобождение блокировок.

Эти проверки не заменяют игровой тест и проверку запросов на живой MariaDB. Обычный быстрый подбор через существующий GiveItem по-прежнему пересекает границы двух ресурсов и не является общей транзакцией выдачи и списания; восстановление после аварийного завершения сервера в середине такой операции не доказано.

Для применения нужен запуск обновлённых thehunt_items и thehunt_loot. Предпочтителен штатный перезапуск сервера: отдельный restart thehunt_items может остановить зависимые ресурсы.

Проверить в игре:

1. /looteditor: создать зону, выбрать предметы, сохранить, закрыть и открыть; проверить оба правила после перезапуска.
2. Подобрать часть лута: зона не пополняется. Забрать остаток, дождаться кулдауна; для режима ухода выйти за радиус и вернуться.
3. Двумя игроками одновременно подобрать/разделить один слот. Проверить перенос в основной инвентарь, карман одежды и экипировку.
4. Проверить слияние лута с лутом, инвентарём и обычным дропом в обе стороны; количество должно совпадать у двух игроков и после переподключения.
5. Перезапустить сервер во время кулдауна и срока жизни предмета: оставшееся время не должно начинаться заново.
6. Удалить/выключить зону, очистить предпросмотр и закрыть редактор во время загрузки моделей; проверить отсутствие оставшихся пропов и возврат управления.

# HUNT · Мёртвые

Ресурс подключён в `server.cfg`. Зоны изначально отсутствуют: создайте их через
админ-панель → «Мир и окружение» → «Мёртвые» или `/zombieeditor`.
Настройки хранятся в автоматически создаваемой таблице `thehunt_zombie_zones` (oxmysql).
Изменения вступают в силу после загрузки обновлённых ресурсов/перезапуска сервера.

## Сеть

- Сервер резервирует каждое создание до отправки единственному клиенту; подтверждение
  проверяет модель, владельца, позицию, измерение и срок заявки. Клиент без заявки не спавнит.
- Постоянный ID имеет вид `epoch:sequence`; network ID не используется как идентичность.
  Проверка тега защищает от повторного использования сетевого ID и entity handle.
- AI выполняется только при `NetworkHasControlOfEntity`. При смене владельца HP не
  переинициализируется; последняя известная позиция передаётся state bag, цель ищется заново.
- Нативные позиция, анимация и HP реплицируются OneSync. Реестр и назначения миграции —
  серверные; вход/переподключение получают снимок, раз в 30 с выполняется сверка.
- Нативный `TaskCombatPed` ведёт погоню и рукопашный бой. Жертва сообщает только
  `EVENT_ENTITY_DAMAGED` от зарегистрированного зомби; близость сама по себе урона не наносит.
  Нативный множитель урона этого NPC к игрокам обнулён, сервер разрешает настроенный урон.
  Проверяются LOS, дистанция контакта, иммунитет, интервал урона и номер подтверждения.
  Смерть сообщает текущий сетевой владелец после клиентского `IsEntityDead`;
  сервер проверяет владельца и выдаёт событие один раз. Серверный HP не используется.
- Отмена создания имеет карантин; незарегистрированные сущности очищаются сервером.
  Restart удаляет сущности по тегу ресурса, а не по модели. NPC cleaner использует тот же тег/реестр.
- Глобальные ограничения: 120 живых/резервируемых, 160 сущностей с трупами, 6 заявок,
  3 создания за серверный тик, 3 мигрирующие группы. Настройки — `config.lua`.

## Особенности

Модели/костюмы: фактические пары из [kibook/redm-undead](https://github.com/kibook/redm-undead/blob/master/undead.lua), 17 моделей и 235 вариантов; чужой AI не копировался.
Для `headshotOnly` используется защитный резерв нативного HP и RDR bone `21030`:
тело не уменьшает отображаемое здоровье, попадание в голову обнуляет нативный HP.
Резерв не переносится на обычные профили. GTA `hitComponent` не используется:
у RedM другой формат `weaponDamageEvent`.
Кусты: приближение через LOS, угол зрения, crouch/stealth и скорость; точное определение
каждого куста не заявляется. Голос: активность Mumble и `proximity.distance` pma-voice,
а не амплитуда микрофона. Пауза и иммунитет игроков временные, до перезапуска/выхода.

## API

Серверные exports: `IsZombie(entity) -> bool,id`, `GetProfile(id) -> settings`,
`SpawnZombie(zoneId) -> reservationId|nil`, `RemoveZombie(id, reason)`,
`SetPlayerAggression(source, enabled)`, `RegisterNoise({x,y,z}, radius, bucket)`,
`GetNearbyZombies(coords, radius, bucket) -> records`.
Клиентские exports: `IsZombie(ped)`, `GetNearbyZombies(coords, radius)`,
`RegisterNoise(kind)` (`shot`, `run`, `walk`, `voice`, `action`).
Локальное серверное событие `thehunt_zombie:died(id, netId, zoneId)` пригодно для
дальнейшего подключения лута; сам ресурс награды/лут не выдаёт.

## Проверки кода

`tests/validate.py` (Python + lupa): выполняет рабочий Lua с подменой natives/БД,
проверяет сетевые гонки, разрешения, жизненный цикл, два клиентских реестра и FSM.
`tests/ui_smoke.py` (Playwright + Edge): проверяет NUI, формы и подтверждения.
Эти проверки не запускают RedM и не имитируют фактическую работу его сетевого движка.

## Исправления 20.09.2026 и проверка в игре

Причина регрессии «появились, стоят, мало, исчезают»: серверный `GetEntityHealth`
нельзя использовать как признак смерти в RedM. В Cfx `SyncTrees_RDR3.h`
метод `GetPedHealth()` возвращает `nullptr`, поэтому серверный native возвращает 0.
Проверка нулевого HP ошибочно ставила `dead=true` живым NPC, отключала их AI,
запускала респавн и удаляла их через срок жизни трупа. Она удалена вместе с такими
же проверками в обработчиках шумов и урона. Тесты теперь моделируют серверный HP=0.

Удаление при отсутствии игроков по `DespawnGrace` сохранено и не запускает
смерть. Исчезновение сущности из стриминга также не запускает респавн после смерти.
Восстановлены клиентский отчёт о настоящей смерти всех профилей и загрузка
`contact.lua`: после частичного отката обработчик попаданий отсутствовал,
хотя принимающая сторона по-прежнему ожидала его подтверждения.

Источники: [RedM sync tree](https://github.com/citizenfx/fivem/blob/master/code/components/citizen-server-impl/include/state/SyncTrees_RDR3.h)
и [реализация серверных natives](https://github.com/citizenfx/fivem/blob/master/code/components/citizen-server-impl/src/state/ServerGameState_Scripting.cpp).

Убраны отсутствующий `SetPedAlertness`, неверный хеш выдачи оружия и флаг
`CA_ALWAYS_FLEE`. Боевые задачи выдаёт только владелец NPC; повторная проверка
восприятия не сбрасывает активную задачу. Навигация переиздаётся при новой цели
или отсутствии прогресса 7 секунд. Скорость погони, угол/дальность зрения,
реакция, слух и агрессия читаются из сохранённых параметров зоны.

«Темп движения» задаёт blend ratio нативной локомоции, а не метры в секунду;
в мирном состоянии скорость ограничена ходьбой. «Интервал урона» ограничивает
частоту потери HP, а не частоту анимаций нативного боя. «Макс. дистанция урона»
фильтрует реальный контакт: увеличение значения не удлиняет руки или оружие NPC.
Сохранение зоны пересоздаёт её группу с новыми настройками и сбрасывает старое ожидание.

После `restart thehunt_zombie` необходим игровой прогон:
1. Кулаки, нож, мачете: попадание, блок, промах, стена; HP изменяется ровно на
   выставленный урон и не чаще интервала. Особо проверить доставку
   `EVENT_ENTITY_DAMAGED` при нулевом множителе на используемой сборке RedM.
2. Два игрока: владелец NPC и удалённая жертва; смена владельца после ухода первого.
   Не должно быть двойного урона, лечения NPC или перезапуска боя каждым клиентом.
3. Скорость 0.3/1.35/3, зрение 1/38, FOV 30/180, агрессия 0, слух, иммунитет,
   потеря цели за стеной, поиск и возвращение в зону.
4. Только голова: тело/голова, труп, респавн; миграция между двумя зонами;
   переподключение и перезапуск с чтением сохранённых настроек из БД.

Автоматические проверки подтверждают логику с подменой natives и работу формы;
перечисленные игровые сценарии в рамках этой правки не выполнены.
